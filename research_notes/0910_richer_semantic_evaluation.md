# 更丰富的报告语义与固定规则评价：第一版原型

2026-09-10。针对当前 Table 1 无法区分“大量积液→少量积液”和“大量积液→仍然大量”的问题，新增独立原型。原有训练缓存、标签、Table 1 评分和论文均未修改。

## 工作方式

```text
原始报告
  ↓ 同一冻结 LLM，每份报告独立抽取，附原文证据
结构化状态：疾病、断言、侧别、部位、程度原文、变化描述
  ↓ 固定的格式与证据校验
冻结的语义缓存；错误和不确定项保留为待复核
  ↓ 固定的归一化词表、比较规则、参考有效字段
疾病有无、程度误差、变化事件 F1 与覆盖率
```

这里的“LLM 筛选”指整理、复核语义，不是只挑模型表现好的病例，也不是删除所有稳定病例。LLM 不输出 F1，不自行决定病例权重。

固定规则的输入是结构化语义。**后续每份新生成报告仍需经过同一版本的语义抽取器**，或未来经过验证的等价专用抽取器；不能把这个设计理解成“先问一次 LLM，之后靠几个关键词就能理解全部自由文本”。

## 保留哪些信息

首版保留现有六疾病作为可计算的固定范围，同时把其他疾病、设备和技术因素作为候选字段收集，等待进一步审阅。字段发现仅用训练集，不能根据测试集上的方法排名修改字段或权重。

| 层级 | 字段 | 处理方式 |
|---|---|---|
| 疾病 | 肺不张、心脏增大、实变、肺水肿、积液、气胸 | 固定名称，不把所有 opacity 自动改成实变 |
| 断言 | 存在／明确不存在／不确定 | 未提及用空列表；冲突的陈述分别保留 |
| 侧别 | 左／右／双侧／未说明 | 左右程度不同拆成两个事实，不取最大值代替 |
| 部位 | 原文中的解剖位置 | 保留原词；首版不强行合并未经验证的同义位置 |
| 程度 | `small`、`moderate-to-large` 等原文 | 保留范围；未说明不能默认轻度 |
| 报告中的变化 | 新出现／增加／减少／消失／不变／混合／未说明 | 与疾病本身的程度分开保存 |
| 比较对象 | `previous radiograph`、`since ___` 等原文 | 先保留，不能自动认定就是所提供的当前检查 |
| 证据 | 支持每条事实的原文句子 | 逐条检查是否能在原报告中找到 |
| 其他内容 | 其他异常、设备、技术因素 | 用于审阅与字段扩展，暂不混入疾病变化评分 |

### 一个对应用户问题的例子

当前状态：`Pleural Effusion / present / right / degree=large`。

真实未来：`Pleural Effusion / present / right / degree=small`，报告还写 `decreased`。

- 预测同样是 small：有无正确、程度正确、改善方向正确。
- 预测仍是 large：有无正确，但程度错误，未命中改善。
- 预测无积液：把改善误写成消退。
- 没有提积液或写“不确定”：不能缩小参考评价范围，在参考可评分字段上记为未命中。

## 程度规则如何定义

原型使用固定的**报告用词等级**，不是临床验证过的容量阈值或医学严重程度金标准。

| 适用发现 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 积液、气胸 | trace / tiny / minimal | small | moderate | large |
| 其他四项的程度描述 | minimal | mild | moderate | severe / marked |

没有列出的词保留原文并标为未映射，不猜等级。是否应合并 `minimal`、`trace`，或者为特定疾病调整词表，要经训练/验证样本复核再冻结，不能事后按方法得分调整。

`moderate-to-large` 保留为区间 `[3,4]`。从 `[3,4]` 到 `[2,2]` 可以证明跨等级下降；从 `[3,4]` 到 `[3,3]` 区间重叠，单靠程度字段不能确定变化。

**同为 small 也不能认定临床稳定。** 积液完全可能都属于 small，但进一步减少。首版只在端点等级严格分离时确定跨等级改善/加重；等级相同或重叠时，进一步判断需要已确认比较对象的变化陈述。

## 变化怎么计算

1. 明确无→明确有：新发；明确有→明确无：消退。
2. 两端明确有、侧别和部位兼容，未来程度区间严格低于当前：改善；严格高于：加重。
3. 两端明确无：持续无该病。
4. 对“仍然存在且不变”、同等级内改善/加重等情况，可以使用报告的明确比较陈述，但必须另外确认其比较对象是提供的当前检查。原型接收逐疾病、逐侧别的 `verified_comparisons` 原文证据映射，不接受 LLM 自报 confidence 作为确认。
5. 未提及、不确定、证据冲突、部位无法对齐、比较对象未确认：保留状态，不能自动归为稳定。

左右可以分别改善和加重。首版分别保存和评价左/右事件，不把它们压成一个整体“改善”；细分区域也可能相反，因此多部位信息不足时不推断净变化。

新发、加重、改善、消退的 F1 都需在参考可判定病例上计算，包含可确认的稳定病例，才能惩罚“真实稳定却预测改善”等误报。所有方法共享同一份参考标签、比较确认和评价掩码；预测漏写或抽取失败不允许删除参考可评分字段。

## 本轮已经实现的范围

- [抽取协议与校验](../code/medworld_table1/semantic_schema.py)：固定 JSON schema、prompt、原文引用检查，保留每次本地模型原始响应。
- [规则与计分](../code/medworld_table1/semantic_metrics.py)：程度区间归一化、侧别状态、端点变化、确认后的比较陈述、疾病 F1、变化 F1、程度误差及覆盖率。
- [本地试运行脚本](../code/medworld_table1/semantic_pilot.py)：从训练集按固定哈希抽 12 对、每患者一对；独立抽取 24 份真实报告，另加 10 份人工构造的验证句。没有向 LLM 同时提供模型预测与标准答案。
- [规则测试](../code/medworld_table1/tests/test_semantic_metrics.py)：程度变化、左右混合、范围重叠、未知预测、抽取失败、比较对象、稳定病例误报、原文证据。

本轮新规则测试与旧有指标回归检查合计 **15 项通过**。这证明相应代码行为符合预定规则，不证明 LLM 抽取达到临床正确率。

[最新逐报告审阅页](../results/semantic_schema_pilot_20260910_v03/index.html)展示原文、LLM 抽取、校验失败和可计算事件。[运行汇总](../results/semantic_schema_pilot_20260910_v03/summary.json)、[人工构造案例得分](../results/semantic_schema_pilot_20260910_v03/synthetic_checks.json)、[具体质量问题](../results/semantic_schema_pilot_20260910_v03/quality_review.md)保留实际结果。此前 v0.1、v0.2 的完整输出也分别保存在 `results/semantic_schema_pilot_20260910` 和 `results/semantic_schema_pilot_20260910_v02`，没有覆盖旧结果。

### 实際试跑结果

最新 v0.3 完成 34/34 次本地请求。10 份人工构造验证句全部通过预先定义的疾病存在状态与变化词检查；这个检查没有覆盖每个语义字段，不能当作 100% 语义正确率。

24 份真实训练报告中，15 份通过全部结构和原文引用校验，9 份需要复核。其中只有 6 对两端都通过。**即使通过校验，仍发现明确阴性被漏标**，因此这些结果还不是可直接使用的参考标签。

在未提供已确认比较对象的条件下，6 对合格报告的 36 个“疾病总体变化”字段均未获得端点规则支持；分侧事件也没有得到支持。原因包含原报告未说明程度/前态、比较对象不明，以及 LLM 抽取遗漏。这个结果不能解读为所有病例稳定，也不能把全部原因归给原始数据；它说明当前抽取器＋保守规则的覆盖率尚不足以替代主表。

人工构造的“当前大量右侧积液，真实未来少量右侧积液”在实际 LLM 输出上得到：

| 预测 | 疾病存在 F1 | 改善事件 F1 | 程度字段准确率 |
|---|---:|---:|---:|
| 少量，较前减少 | 1 | 1 | 1 |
| 仍大量，无变化 | 1 | 0 | 0 |
| 无积液 | 0 | 0 | 0 |
| 漏写积液／只写可能少量积液 | 0 | 0 | 0 |

这些是单个构造病例的说明分数，不是模型测试集的 Table 1 成绩。

## 目前不能直接替换 Table 1

- 原文证据存在只证明引用有来源，不能证明修饰词正确关联到了疾病。比如同一句中的 `small` 可能修饰积液，LLM 却把它也分配给肺不张。
- 单份报告中的 `improved` 常有不明比较对象。首版保留这些字段，但未自动把真实样本的比较对象确认为当前检查，所以变化覆盖率可能低。这是需要解决的数据证据问题，不能靠默认“上一次就是当前”提高覆盖率。
- 目前程度误差是探索性字段平均，总体字段和左右字段存在重叠，尚未冻结适合主表的疾病／侧别权重。它不是新的正式 Table 1 分数。
- 现有 Finding AUPRC 的疾病头仍输出疾病有无概率；丰富报告语义不会自动产生程度概率或变化概率。
- 新的检索距离及候选池尚未接入。Future R@1 后续需要固定共同可比字段与权重，不能让模型漏写字段改变其检索距离的有效范围。
- 12 对用于发现问题和验证流程，不能估计全库语义质量。正式扩展需要预先抽样的训练/验证审阅集，重点核验变化、稳定、不确定和抽取器分歧，同时保留随机样本。

后续应区分两种评价目标：**未来报告内容是否忠实**，可以评价生成报告是否保留参考报告中的程度和明确变化陈述；**从所给 t0 到 t1 的真实病情变化是否预测正确**，则还需要端点证据或比较对象确认。原型现在实现的是后者的保守事件规则；尚未单独实现前者的变化陈述一致性指标。两者不能混成一个含义不清的 Transition F1。

下一步应先完成字段和抽取质量的审阅，再冻结协议重算各方法。主表中的疾病有无、程度、变化和检索应各自说明评价范围，避免把一个粗粒度分数解释为完整病情演变能力。
