# MedWorld-JEPA：实验现象与诊断计划

日期：2026-09-09。用途：团队讨论。本文整理 9 月 8 日启动的 8 小时小模型实验，以及之后基于保存结果完成的分析。

后续补充：[纵向配对质量审计](0909_pair_quality_audit.md)。包含实际 CXR/IV 连接、时间跨度、住院边界、弱标签覆盖、采集差异，以及保存预测在严格子集上的结果；仍未启动新训练。

进一步补充：[全量 CXR + IV 连接规模及六组示例](0909_mimic_linked_cohort_capacity.md)。后续数据必须连接临床数据库；已统计完整本地库，尚未重建训练缓存或训练。

**当前决定：先讨论，不启动新训练，不更换 decoder。** 本次整理只读取代码、已有日志、checkpoint 和评估结果；没有启动新的模型训练或 GPU 前向实验。后面的诊断和训练方案均为待做计划。

**目前最需要回答的问题：报告生成模板化，究竟来自 Stage-1 状态训练不足、8 个 slots 的信息不足、LWM 预测失真，还是 decoder 没有利用好状态？** 已有结果尚不能把原因锁定在其中一个模块。

**1. 实际训练了什么**

冻结 V-JEPA 2.1 ViT-B 提取图像特征，经可训练 visual adapter 和 Qwen3.5-0.8B 编码器，输出 8 个 state tokens。每个 state token 宽度为 1,024，单个病例的状态形状为 `8 × 1024`。

需要区分两个对象：输入 slot embeddings `U` 是跨病例共享的可学习参数；输出 state tokens `S` 是随输入图像、报告和编码器参数变化的激活。固定编码器参数不会让所有病例得到相同的 `S`。

| 环节 | 本轮实际实现 |
|---|---|
| Stage 1，约 1 小时 | 仅输入当前图像；8 个 state tokens 用于当前报告生成和六疾病分类 |
| 疾病分类读取 | 对 8 个输出 tokens 求均值，再经 LayerNorm 和线性疾病头；未知标签不参与 BCE |
| 报告生成读取 | 整组 8 个 tokens 经投影后作为连续输入条件，交给语言 decoder |
| Stage 2，约 7 小时 | 当前图像＋当前报告 → 当前 state；LWM 接收当前 state＋horizon → 预测未来 state |
| 第二阶段监督 | 未来 latent MSE＋未来报告 CE＋未来疾病 BCE＋当前影像分类 replay |
| 未来目标编码器 | 固定的 Stage-1 副本，读取真实未来图像和报告，只提供监督 |
| 分割、超分 | 本轮没有接入，也没有相应监督或评估 |
| 独立指令式疾病识别 | 没有另做；本轮六疾病分类不等于完整的指令任务训练 |

第二阶段损失权重为 `latent + report CE + 0.5 × finding BCE + 0.1 × current finding replay`。Stage 1 为 `report CE + 0.5 × finding BCE`。Stage 2 没有保留当前报告生成 replay。

这轮没有给 8 个 slots 指定“哪个负责分割、哪个负责疾病”等独立语义，也没有单独监督每个 slot。任务损失经共享状态回传。因而“用了 8 个 slots”不代表已经学出了 8 种功能。

训练/验证/测试分别为 12,000 / 645 / 1,000 对检查，患者互不重叠。测试集为 195 位患者。该 pilot 的报告可用时间戳无法核实，属于回顾性、当前报告已可用的设置。

**2. Decoder 和冻结对照的确切含义**

报告 decoder 使用预训练 Qwen3.5-0.8B 的语言模型主体；主体参数冻结，训练独立的 rank-8 LoRA 和新建的 state 投影层。语言能力有预训练基础，但如何读取我们定义的 state，需要这次任务训练建立。实际输入顺序为 `投影后的 8 个 state tokens → 固定聊天提示 → 输出报告`。

Stage 1 训练当前报告生成，Stage 2 继续训练未来报告生成。主模型和冻结对照拥有相同的 Stage-1 decoder 初始化，第二阶段各自继续训练，最终 decoder 权重并不相同。

| 第二阶段 | 冻结 Stage-1 对照 | 完整方法 |
|---|---|---|
| 当前状态编码器，包括 adapter、U、编码器 LoRA | 冻结 | 更新 |
| LWM、报告 decoder、疾病头 | 更新 | 更新 |
| 未来目标编码器 | 固定 Stage-1 副本 | 相同的固定 Stage-1 副本 |
| 第二阶段数据、损失、更新步数 | 相同，5,301 步 | 相同，5,301 步 |

该对照可简写为 **Ours w/ frozen state encoder**。它仍接受未来监督，不能用来单独检验“有没有 future loss”，也没有比较“有 slots / 无 slots”。

**4. 已观察到的实验现象**

**4.1 报告输出严重模板化。** 以下为完整字符串精确去重，没有合并同义表达。

| 方法 | 不同报告数 / 1,000 | 最常见报告出现次数 | 前五种报告占比 |
|---|---:|---:|---:|
| Copy Current | 997 | 3 | 0.8% |
| 直接 Qwen | 952 | 15 | 3.5% |
| 冻结 Stage-1 | 12 | 630 | 93.6% |
| 完整方法 | 41 | 572 | 84.5% |

完整方法最常见的报告描述心影增大、肺水肿、双侧积液和肺底肺不张，并称整体变化不大。这里确认的是报告输出退化，尚未测量输出状态 S 的方差、有效秩或患者区分能力，不能直接宣称 latent 已塌缩。

**4.2 疾病评分与报告表达没有同步。**

| 疾病 | 冻结对照 AP | 完整方法 AP | 直接 Qwen AP | 完整方法报告 F1 |
|---|---:|---:|---:|---:|
| 肺不张 | 0.9901 | 0.9973 | 0.9942 | 0.8684 |
| 心脏增大 | 0.8100 | 0.9245 | 0.9280 | 0.7828 |
| 实变 | 0.6577 | 0.6623 | 0.6934 | 0.0000 |
| 肺水肿 | 0.7955 | 0.8801 | 0.8929 | 0.7535 |
| 胸腔积液 | 0.7784 | 0.8934 | 0.8476 | 0.8222 |
| 气胸 | 0.0718 | 0.4375 | 0.4254 | 0.0625 |

主模型 1,000 份报告中，CheXbert 没有识别出任何实变阳性，仅识别出 6 份气胸阳性。相对冻结对照的 macro AP 增益为 0.1153，其中约 53% 来自气胸这一项。

不能概括为“所有经过 decoder 的指标都下降”：相对冻结对照，完整方法的 CheXbert 和 RadGraph 有小幅提升，Transition F1 和固定候选池 R@1 则较低。相对直接 Qwen，完整方法的报告标签 F1 较高，RadGraph 和 R@1 较低。

**4.3 AP 的收益主要出现在可观测标签稳定的病例。**

| 真值分组 | 检查对数 | 冻结对照 AP | 完整方法 AP | 直接 Qwen AP |
|---|---:|---:|---:|---:|
| 可观测字段稳定 | 586 | 0.7089 | 0.9101 | 0.9123 |
| 至少一个可观测变化 | 169 | 0.6797 | 0.6664 | 0.6484 |

另有 245 对没有任何当前—未来同时可比较的疾病字段，不能当作稳定病例。上述分组来自报告标签，不代表已完整掌握真实病情变化。在能判断的 755 对中，约 78% 的可观测标签稳定，这使复制当前报告成为强基线。

按 195 位患者进行 2,000 次配对 bootstrap：完整方法相对冻结对照的 AP 差值为 0.1153，95% 区间 [0.0823, 0.1646]；相对直接 Qwen仅为 0.0023，区间 [-0.0253, 0.0379]。后者没有可靠优势。区间不包含不同训练 seed 带来的不确定性；本轮只训练一个 seed。

**4.4 标签覆盖与宏平均会放大部分表面收益。**

- 6,000 个未来疾病字段中只有 2,611 个可评估，当前与未来同时可评估的字段只有 1,524 个。
- 肺不张的有效未来标签是 329 阳性 / 331 例，常量分数的 AP 已有 0.9940。因此 0.9973 不表示接近完美的区分能力；这也不是完整队列的患病率。
- 真实报告 blank/uncertain 字段被排除，预测的多余异常若落在这些字段上不会被该字段惩罚。不能为了提高结果而事后把所有 blank 改成阴性。
- 事后把主模型最常见的那份报告用于全部 1,000 个病例，CheXbert F1 为 0.5826、Transition F1 为 0.2304，均高于主模型实际报告。这是测试输出选出的诊断常量，不能当作预先设定的正式 baseline。它说明超过 Copy Current 的变化分数仍不自动等于患者特异预测。

**4.5 冻结对照的 Transition F1 领先受单例影响。**

官方主分数等权平均 11 个有真值支持的事件类别。肺不张新发只有 1 例：冻结对照该项 F1=1，完整方法为 0，单项就为冻结对照增加 0.0909 的总分。

| 计分方式 | 直接 Qwen | 冻结对照 | 完整方法 |
|---|---:|---:|---:|
| 原定 11 类事件宏平均 | 0.1551 | 0.2720 | 0.1994 |
| 事后去掉肺不张单例新发项 | 0.1707 | 0.1992 | 0.2194 |
| 所有可评估事件 micro F1 | 0.2288 | 0.3447 | 0.3504 |

后两行只作敏感性诊断，不替换主表。189 个真实变化事件中，完整方法检出 65 个、误报 117 个变化；冻结对照为 71 / 152，直接 Qwen 为 31 / 51。

**4.6 检索没有显示清晰的患者特异优势，评价空间也较粗。**

原定 32 候选在当前测试集中无可行 query：非空匹配分组有 417 个，一个分组最多只有 13 位患者。四候选结果已按用户决定列入本轮表格，仍需保留其 37.6% 覆盖率。

四候选的 376 个 query 中，有 96 个的全部候选在可评估疾病字段上完全相同。即使使用真实目标疾病标签，按当前并列规则，平均 R@1 也只有 0.5328。因此该指标同时受模型输出和六疾病 schema 区分能力限制。

补充的八候选纳入 120 对、53 位患者：Copy Current 0.1694，直接 Qwen 0.1495，冻结对照 0.1225，完整方法 0.1147，随机排序参考 0.125。不同候选数对应不同纳入子集，不能直接比较。没有检验完整方法是否显著低于随机。

另外，完整方法在 7–30 天组的报告 CheXbert F1 为 0.3090，Copy Current 为 0.4884；不同 horizon 的病种构成和支持量不同，不能仅据此判断时间条件是否被使用。

**4.7 训练损失下降，但 Stage 1 的训练和验证不足以确认状态已经学好。**

Stage 1 完成 1,207 个更新，有效 batch=8，共 9,656 次图像样本呈现。复现确定性采样器后，实际见过 7,891 个不同训练观测，占可用 22,781 个训练观测的 **34.64%**；这不是一次完整的数据遍历。

| Stage-1 训练记录 | 报告 CE | 疾病 BCE |
|---|---:|---:|
| 前 100 步均值 | 2.1869 | 0.5532 |
| 后 100 步均值 | 1.5443 | 0.4531 |
| 验证 step 500，固定 64 对 | 1.6109 | 0.4149 |
| 验证 step 1000，固定 64 对 | 1.5206 | 0.3903 |

训练日志支持“优化有推进”，不支持“已经收敛或已学到通用状态”。最后一个 Stage-1 验证点不是其最终 step 1207；尚无 Stage-1 独立当前疾病 AP、自由生成质量、分割 Dice 或超分 PSNR/SSIM。

第二阶段完整方法的验证报告 CE 从首次记录的 1.5215 降至 1.4070，疾病 BCE 从 0.4424 降至 0.2971，latent MSE 从 0.1993 到 0.1965，后半程基本处于平台。冻结对照最终 latent MSE 为 0.1894，更低的 latent loss 没有对应全面更好的临床指标。

直接 Qwen 在同样 8 小时内完成 10,709 次更新，纵向样本呈现次数约为完整方法第二阶段的两倍；这不是等更新数或等 FLOPs 的比较。其验证疾病 BCE 后期回升，可能有过拟合或校准恶化，但仅使用 64 对的验证曲线还不足以锁定原因。

完整方法两个阶段记录的全局梯度 norm 均大于裁剪阈值 1，因此所有记录步骤都进行了全局梯度裁剪。梯度及 loss 保持有限。尚无逐任务、逐模块的梯度范数或梯度夹角日志，不能由全局 norm 推断哪个任务没有优化 slots，也不能把常规梯度裁剪直接认定为错误。

**4.8 Checkpoint 确认参数确实有更新，但参数变化不等于表示有效。**

本次仅在 CPU 比较已有紧凑 checkpoint：冻结对照最终保存的 236 个编码器参数张量，与 Stage 1 全部完全一致；完整方法这 236 个张量全部发生变化；其固定目标编码器仍与 Stage 1 完全一致。

Stage 1 → 完整方法最终 checkpoint，输入 slot embeddings U 的相对 L2 变化为 27.46%，visual adapter 为 24.81%，decoder 投影为 24.91%。这排除了“第二阶段实际上完全没更新这些模块”的解释，但没有证明 8 个输出 S 提供了有用信息；这里比较的是参数，不是激活。

还有一个需要检查的分布变化：Stage 1 只训练 image-only 状态，Stage 2 的当前与固定目标状态都加入报告。固定目标编码器没有获得第二阶段的图文适配，而当前编码器可训练与否恰是两组差别之一。因此疾病评分收益可能包含图文输入适配，不能全部归因于未来 dynamics。

CXAS 权重当前位于 `/home/data2/chk/.cxas/weights/UNet_ResNet50_default.pth`，约 881 MB。当前读取 `process_file()` 时内部使用 `torch.no_grad()`，输出还包含阈值化二值 mask。后续若要用分割 loss 优化 slots，需要接入可微分的模型 logits 和 state 条件分支；只调用现有推理接口、保存 mask，不会产生通向 slots 的梯度。

**6. 当前假设，以及什么证据能区分它们**

| 假设 | 当前支持线索 | 尚缺的检查 |
|---|---|---|
| Stage-1 状态训练不充分 | 仅 1 小时、覆盖约 35% 的训练观测，只有两个任务 | Stage-1 当前疾病和自由生成评估；后续匹配训练预算的对照 |
| 状态只保留粗粒度疾病信息 | 疾病评分存在区分度，但报告缺少细节 | 正确/打乱 state 对头和 decoder 的影响；状态变异与更多标签读出 |
| Decoder 忽略或难以读取状态 | 输出集中在极少数模板，teacher-forcing CE 仍下降 | 固定 decoder 的条件扰动；缓存生成与完整前向的一致性 |
| LWM 没有增加有效未来信息 | AP 增益主要出现在稳定病例，检索接近随机参考 | 当前状态 persistence、预测未来状态、真实未来状态的匹配读出 |
| 固定目标编码器或输入分布变化有影响 | image-only Stage 1 切换到图文 Stage 2，target 固定 | 分开检查 image-only / 图文状态及目标—预测分布 |
| 指标覆盖和候选 schema 太粗 | 稀有事件权重高、未知字段多、候选并列多 | 支持量、覆盖率、固定分母和候选可区分性审计；不能事后挑分数高的规则 |

目前没有验证到具体的生成实现 bug，也没有证据能确认“decoder 一定是唯一根因”或“8 个 slots 根本没有用”。

**7. 简短验证计划：先检查，之后再决定是否训练**

**第一步：检查已有 checkpoint，不更新参数。** 先固定验证集，所有条件共享患者、样本顺序、提示、生成长度和解码参数。先用 64 对做实现自检，再扩至全部 645 对验证集；不要用已经查看过的测试结果选方案。

| 检查 | 怎么做 | 要回答什么 |
|---|---|---|
| Stage-1 当前任务 | 仅当前图像 → Stage-1 state → 已有分类头/报告 decoder；记录 AP、BCE、自由生成指标和重复率 | 在引入 LWM 前，状态和 decoder 是否已出现问题？已有头的结果仅是系统诊断，不是新的冻结表征 probe |
| 条件敏感性 | 固定模型，比较正确 state、不同患者打乱 state、训练集均值 state；第二阶段打乱优先在同 horizon 内完成 | 疾病头和文字 decoder 分别使用了多少患者信息？固定/打乱输入有分布变化，需联合解释 |
| Horizon 敏感性 | 固定当前 state，只修改 horizon | LWM 是否使用时间条件？输出变化本身还不等于变化正确 |
| 生成实现 | 同一 state 和同一生成前缀，比较缓存逐步解码与完整前向的下一 token logits；检查 mask、position、EOS 和批量行为 | 排除生成实现造成退化的可能 |
| 信息所在位置 | 对正确、打乱输入记录 state 的跨患者方差、slot 间相似度，以及疾病/文本输出变化 | 检查患者差异和 slot 冗余；高 cosine 或低秩单独都不足以判定无用 |

可以另做“真实未来 state → 报告”的 observation-conditioned 重建诊断，与预测未来 state 对照。真实未来 state 如果包含真实报告，该检查具有文本重建成分；现有 decoder 又可能只适应预测状态分布，因此它不是严格性能上界。若两者都差，仍不能仅据此判定 decoder 是唯一原因。

**第二步：如果决定做短训练，先只诊断读出，不动编码器和 LWM。当前未启动。**

- 先在少量训练病例上检查 state 条件读出能否拟合；这是训练集可拟合性检查，不计作泛化结果。
- 使用固定目标编码器的训练集真实状态，拟合一个 observation-only 读出后冻结；在相同目标空间比较真实目标、预测未来和当前 persistence 状态，帮助分离状态预测与读出误差。Persistence 应由同一个固定目标编码器编码当前观测，不能直接把不同编码器空间中的当前 S 混入比较。
- 若要改善实际未来报告系统，保留旧 decoder 继续训练的对照，再试一个新的条件注入方案。初次可定 200 个更新作可行性检查，数据、有效 batch、更新数和验证规则一致；预算是否足够以学习曲线为依据，不预先承诺效果。
- 优先一次只改变一项：state 投影/注入位置、条件融合结构或 LoRA 适配范围；先不同时更换语言骨干、训练数据和所有超参数。
- “统一 decoder”需要区分两种用途：统一评估读出可以共用一个固定的目标空间 decoder；实际系统适配则是统一架构、初始权重、数据和训练预算，各系统分别训练，不假定最终权重相同。
- 后续若记录逐任务梯度，分别报告 CE/BCE/latent 对 U、输出 S、adapter、编码器 LoRA 的梯度范数和方向；这些检查也应与优化更新区分。

判断改进时同时看报告条件敏感性、临床指标、遗漏/新增异常和多样性；增加采样温度或减少字面重复本身不构成成功。

**第三步：分割与超分先明确接口，再决定加入 Stage 1。当前未接入、未训练。**

分割可从已有 CXAS 图像骨干和 UNet 解码结构出发，先选左肺、右肺、心脏等明确类别。图像分支读取原始当前图像 X，state 分支读取同一图像得到的 8 个 S，再用可训练的条件融合模块将 S 接入分割网络。使用 logits 计算监督损失，使梯度可以回到状态编码器；不复用 JEPA 的 D 作为空间 decoder 旁路。

已有 CXAS mask 可用于探索伪标签训练流程；若用它们作监督，应明确是教师模型蒸馏，独立评估需要人工标注或与教师生成过程独立的依据。解剖分割能检查静态结构表达，但不保证提高未来病程预测。

超分可先定义一个可控的 2×任务：例如固定裁剪的 384×384 图像作 HR，预先固定退化操作得到 192×192 LR。恢复网络直接读取 LR；JEPA/VLM 状态分支也只能读取由同一 LR 得到的输入，即使为适配 JEPA 尺寸而上采样，也不能读取 HR 或其报告。使用 MSE 训练，PSNR/SSIM 和固定病例图作评价。这个设置是待讨论方案，目前没有生成数据或选择新的超分模型。

两类任务都应先完成下面的匹配对照，防止图像网络完成任务而忽略 S：

| 条件 | 图像分支 | 状态 |
|---|---|---|
| Image-only 对照 | 相同 | 从训练开始使用固定 null state |
| Stage-1 状态 | 相同 | 冻结 Stage-1 编码器得到的 S |
| 完整方法状态 | 相同 | 冻结 Stage-2 编码器得到的 S |
| 后续严格 no-future 对照 | 相同 | 在匹配检查曝光和更新预算下只做单时点训练的编码器 |

各组使用相同的新读出结构、初始化、标注和训练预算；主要比较用 image-only 状态。单独在测试时把 state 置零只能作为扰动诊断，不能代替从训练开始匹配的 image-only 对照。

只有在移除 LWM、冻结编码器之后，新的匹配下游头仍获得收益，才能支持“未来训练改善了可复用当前表征”。未来预测收益还应单独通过 persistence 和 w/o latent loss 等对照验证。改变 slot 数量属于之后的问题，暂不把多个因素一起改动。

**8. 讨论时需要决定的事项**

1. 首先验证 Stage-1 状态/读出是否合格，还是先排除生成实现问题？建议先完成无需训练的两组检查。
2. 如何定义“decoder 更好”：提高患者条件依赖和临床内容正确性，而不只降低 CE 或增加文字多样性。
3. 分割先用哪些类别和哪类真值？已有 CXAS 更适合作为图像骨干、教师，还是两者之一？
4. 用户记忆中的超分资源是否就是旧 IXI 重建？目前独立超分模型路径仍未定位。
5. Stage 1 是否需要更充分的数据覆盖及空间任务监督？这需要后续匹配实验验证，不能预先归因。
6. 本轮 4 候选检索和稀有事件指标是否足以承载论文结论？正式结果需要固定协议并保留新的确认性评价。
