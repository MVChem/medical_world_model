我查了一圈，结论比较明确：

### 1. `X-WIN + LWM` 可以做，但不要把它包装成“X-WIN 原方法”

**实现难度不高。** X-WIN 已经公开代码，定位本身也是 CXR representation/world model。它原论文主要做的是 CXR 表征学习，下游看 AUROC、few-shot，以及 projection/CT reconstruction 的 PSNR/SSIM；**它没有做患者纵向 future report prediction**。

所以：

> **X-WIN encoder + our matched LWM + same text decoder**

是一个合理 baseline，但它本质是**representation baseline / encoder swap**，不是“复现 X-WIN 的 forecasting method”。

这样做才公平：所有 longitudinal pairs、horizon、LWM 容量、text decoder、训练步数全部一样，只替换 `current-state encoder`。如果 MedWorld-JEPA 用 image+report，而 X-WIN 只吃 image，那就又不公平了；最好给 X-WIN 后面也接同一套 text/VLM fusion。

我倾向把它放在 **ablation / representation baseline**，不一定占 Table 1 最核心的位置。

---

### 2. `CLARITY-style` 我反而建议从主表删掉

CLARITY 虽然**已经开源代码**，但原任务差得比较远：多序列 glioma MRI + clinical context + treatment action + time → latent disease trajectory + survival / treatment ranking。它用了 BrainIAC、MedGemma、time-aware latent predictor 和 survival head。

要迁到我们这里，你得：

- MRI → CXR
- treatment-conditioned → observational horizon-conditioned
- survival target → future latent
- 再增加 future report decoder

这改完基本已经是我们自己重新设计的 baseline 了。

有意思的是，**CLARITY 自己就遇到了这个问题**：它说原始 MeWM 是 CT、数据又不公开，所以无法直接比较，最后自己重新实现了一个 `MeWM*`，明确用 `*` 标记为 re-implementation。

所以 CLARITY-style **可以 appendix 做 adapted baseline**，但我不建议放 Table 1 当核心竞争方法。Reviewer 很容易问：

> “你比较的是 CLARITY，还是你自己根据 CLARITY 写的 Transformer？”

---

## 3. 你记得的 ICCV 2025 那篇就是 **Medical World Model (MeWM)**

这篇确实值得参考，但它和我们任务也不完全一样。它是 treatment → future tumor simulation。

它的指标其实分三类：

| 任务 | MeWM 用的指标 |
|---|---|
| Future tumor generation | Radiologist Turing test: Sensitivity / Specificity / Accuracy；**FID、LPIPS** |
| Survival prediction | **MSE、C-index、log-rank p-value** |
| Treatment selection | **F1、Jaccard、Precision、Recall** |

未来图像部分，它比较 SynTumor、Pixel2Cancer、DiffTumor、TextoMorph；Table 1 就是 radiologist visual Turing test + FID/LPIPS。

治疗决策部分很有意思，它直接比较了：

**Qwen2.5-VL、GPT-4o、Claude-3.7-Sonnet、CT2Rep、MedGPT、HuatuoGPT-Vision、MeWM。** 

这里 **GPT-4o / Claude 是闭源模型，但他们不是“自己实现”**，就是作为 black-box multimodal model 给 pre-treatment CT + prompt，让它预测 treatment combo。论文明确描述了这种 prompting comparison。

所以 medical world model paper 里用闭源 API 当 baseline 是完全存在的。但你已经说我们先不考虑闭源，我同意，省掉很多不可复现的问题。

## 4. 我觉得我们现在的 metrics 基本是对的

更直接的证据来自 **longitudinal CXR/report generation**。

HERGen 在 Longitudinal MIMIC-CXR 上就是：

**BLEU-1/2/3/4 + METEOR + ROUGE-L + Clinical Precision / Recall / F1**。而且 HERGen 很严谨：有公开代码的方法，他们在自己的 preprocessing 上**重新跑**；没代码的方法，就用原论文数字并标 `†`，明确说明不能严格比较。

更关键的是刚出的 BMVC 2026 **CheXGround**。它的 longitudinal findings generation 几乎已经把我们想要的指标集验证了一遍：

> **BLEU-4, ROUGE-L, METEOR, CheXbert-F1 micro/macro, RadGraph-F1, Temporal F1**

而且它的 baselines 就包括 HERGen、CheXagent、MedGemma、MAIRA-2、Libra 等。

所以你现在 plan 里的 **ROUGE-L + RadGraph + CheXbert + temporal transition** 非常合理。

我会稍微改成：

| Metric | 保留？ |
|---|---|
| **Future R@1** | ✅ 我们特有，但很好，证明 patient-specific future |
| **Finding AUPRC** | ✅ 但前提是从 latent 输出疾病**概率** |
| **Transition Macro-F1** | ✅ 强烈保留 |
| **RadGraph F1** | ✅ |
| **CheXbert Macro-F1** | ✅ |
| **ROUGE-L** | ✅ |
| BLEU-4 | Appendix |
| METEOR | Appendix |

尤其 **Transition F1** 很重要。CheXGround 现在也专门报告 `F1_temp`，因为普通 CheXbert F1 不能区分“疾病预测对了”和“变化方向预测对了”。

# 5. 我现在会重新定 Table 1 的 methods

我觉得不要硬塞一堆“改造后的 world model”。最干净的是：

| Type | Method | 开放情况 | 我建议 |
|---|---|---|---|
| Trivial | **Copy current report** | — | **必须** |
| General VLM | **Qwen3.5-9B** | Open weights, Apache-2.0 | **必须**  |
| Medical VLM | **MedGemma** | 权重可获取，但 gated / Health AI license | **必须**  |
| CXR VLM | **CheXagent** | Code + weights available | **推荐**  |
| CXR report VLM | **MAIRA-2 7B** | Gated weights；research license | **推荐**  |
| Matched control | **Stage-1 state + matched LWM + decoder** | 我们实现 | **必须** |
| Representation baseline | **X-WIN + matched LWM + decoder** | Code available | 可选 |
| Ours | **MedWorld-JEPA** | — | **必须** |

### 为什么我现在更喜欢 MAIRA-2，而不是 CLARITY-style？

因为 **MAIRA-2 本身就是 7B 左右的 CXR report-generation medical VLM**，而且 checkpoint 可以直接跑。

虽然它原来是“看到当前 X-ray → 写当前 report”，我们只需要把它 **fine-tune 成 `current evidence + horizon → future report`**。这是非常自然的 task adaptation。

相比之下，CLARITY 要把整套 disease/treatment world model 拆掉重装，解释成本很高。
